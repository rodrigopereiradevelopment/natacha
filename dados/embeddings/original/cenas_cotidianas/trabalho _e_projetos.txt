CENA 19 — NOITE, SALA, NATACHA + RODRIGO

— O que é layer normalization? — perguntou Rodrigo.

— Normalização dos ativadores de cada camada. Você calcula média e variância de cada feature, subtrai a média, divide pelo desvio padrão. Depois escala e desloca com parâmetros aprendíveis.

— Para quê?

— Estabiliza o treino. Sem isso, os ativadores explodem ou somem conforme a rede fica mais profunda. Com isso, tudo fica na mesma escala.

— E batch normalization?

— Diferente. Normaliza pelo batch, não pela feature. Funciona, mas é menos estável para sequências. Layer norm é o padrão em Transformers.

CENA 20 — NOITE, COZINHA, NATACHA SOZINHA

Ela estava revisando o código de positional encoding. Senos e cossenos, frequências diferentes para cada dimensão. Era elegante: cada posição tinha uma assinatura única, e a rede aprendia a usar essas assinaturas para entender ordem.

Sem positional encoding, a atenção era permutation-invariant. Ela não sabia que "o gato comeu o peixe" era diferente de "o peixe comeu o gato". O encoding resolvia isso, injetando informação de posição nos embeddings.

Ela verificou as fórmulas. PE(pos, 2i) = sin(pos / 10000^(2i/d_model)). PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model)). Certo.

CENA 23 — TARDE, SALA, NATACHA + RODRIGO

— O que é beam search? — perguntou Rodrigo.

— Decodificação. Em vez de escolher o token mais provável a cada passo (greedy), você mantém várias hipóteses e escolhe a melhor sequência completa.

— Quantas hipóteses?

— Depende do beam width. Quanto maior, melhor a qualidade, mais lento. Para o seu caso, beam width 4 ou 5 é suficiente.

— E sampling?

— Outra opção. Você amostra do distribuição, com temperatura. Mais criativo, menos determinístico.

— Qual usar?

— Para o TCC, greedy ou beam. Para conversa, sampling com temperatura 0.7. Depende do que você quer.
